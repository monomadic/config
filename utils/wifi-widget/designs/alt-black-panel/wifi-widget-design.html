A Wi‑Fi menu that says when something is wrong

Same parts as the volume widget: bare glyphs, a pill after the name, a spec line, a meter on every row and a circular button at the end. In v2 the network you're on is one larger menu item holding the link numbers, internet status, the router's WAN and addresses you can copy by hovering. A new Login page state covers captive portals. The network you're on is one menu itemv2

The top of the menu used to have a separate stats panel above a row that repeated it. Now there is one larger item: the same row as every network below it, with an inset underneath in three groups. Link: signal, noise, rate. Outside: internet check, router WAN, speed test. Addresses: IP, gateway, MAC, node. The network you're on is no longer repeated in the Networks list.

Hover to copy. The IP, gateway, MAC and node rows highlight on hover and copy on click, so the separate Copy IP Address item is gone. MAC is this Mac's address on the current network, tagged private when macOS is using a per-network private address.

Refresh sits in the Networks headerv2

A right-aligned Refresh on the Networks label rescans nearby networks and reruns the internet check. It shows Scanning… while it works. It replaces the Check Again button that v1 used for No internet.

Pins

The circle at the end of each row cycles between three states. Open house = no rule. Blue house = Home: the network you expect to be on. White gauge = Metered: dashed border, amber while you're connected, and it counts data. Home turns red only when macOS drops it and falls back to another network. If you join a café network yourself, Home is simply dimmed as not in range.

Why the bar is SNR

The same −65 dBm can be excellent or unusable

RSSI alone doesn't tell you much. What matters is how far the signal sits above the noise floor: −65 against −95 of noise is a 30 dB link, and against −75 it is a 10 dB link that drops calls. CoreWLAN reports both numbers, so every bar is SNR on a 0–50 dB scale. The meter notches mark the 15 and 25 dB tier edges.

No internet and Login page don't show up in the signal. No internet sits at 41 dB, next to Healthy. Only the internet check catches them. The system icon shows full bars either way.

Below 15 dB turns red and the Smart Bar shows the raw dBm, because at that point the number is worth reading. Between 15 and 25 dB the bar stays monochrome: a fair link is not an alert.

Outside the Wi‑Fi

Can the widget see past the router?

Partly, and more on your own network than on others. I probed yours, read-only: 192.168.1.1 is your GL.iNet GL-BE9300 (Flint 3), running OpenWrt with GL's 4.x JSON-RPC API at /rpc, which answered a login challenge. The generic routes, UPnP and NAT-PMP, got no answer.

Works on your router

Flint 3 API, with the admin password

The password is saved in Keychain once, per network, and the WAN row appears only for that network. OpenWrt tracks WAN up/down and uptime, which uplink is active (the Flint 3 does multi-WAN failover across Ethernet, repeater and tethering) and byte counters. The counters give whole-home live throughput, drawn as the WAN sparkline. The exact RPC methods still need checking after logging in.

This is what lets No internet say where the fault is: the router's WAN is down, rather than just "router answers, internet doesn't".

Link speed, not plan speed

What the router can't tell you

The Flint 3's WAN port negotiates up to 2.5 Gbps, but that's the cable to the modem, not your ISP plan. Line sync rate is only available when the router is also the DSL/cable modem. So the plan-speed figure comes from a test instead.

Works everywhere

Speed test via networkQuality

macOS ships Apple's own tester (networkQuality -c outputs JSON). It measures download and upload capacity and responsiveness, and takes about 15 s. It runs only when you click Test, and it's disabled on Metered networks because each run uses hundreds of MB.

Rarely available

UPnP IGD and SNMP

Where UPnP is on, GetCommonLinkProperties and GetTotalBytes* give WAN rate and counters for any router with no login. It's off on yours, often off elsewhere, and the rates it reports are often wrong. It's worth trying automatically, but don't build the design around it.

Build notes

What it reads, and from where

CoreWLAN through objc2

CWInterface provides rssiValue, noiseMeasurement, transmitRate, wlanChannel, activePHYMode, bssid and hardwareAddress (this Mac's address, which is private when bit 0x02 of the first octet is set). CWEventDelegate redraws on each event, so there's no poll loop.

Login-page detectionv2

The widget loads http://captive.apple.com/hotspot-detect.html. Any response other than its Success body means a login page is intercepting traffic. The redirect host appears on the Internet row. Open Login Page opens that same plain-HTTP URL in your default browser, so the portal redirects there and your password manager works. Portals that hijack DNS instead of redirecting are caught too.

Location Services gate

SSID and BSSID come back nil until the process has Location authorization. Without it, the card reads Wi‑Fi · 6 GHz, the Node row is hidden, and a single menu item asks for permission. The pins need the SSID, so they appear as unavailable rather than disappearing.

Scans on open and on Refresh

scanForNetworks takes 1–3 s and briefly takes over the radio, so it runs only when the menu opens and when you click Refresh. Rejoin disconnects and reconnects to the strongest access point for the SSID. If macOS asks for an admin password, it opens Wi‑Fi Settings instead.

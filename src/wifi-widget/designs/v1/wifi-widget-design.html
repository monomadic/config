wifi-widget · guard design, carried over from volume-widget

A Wi‑Fi menu that says when something is wrong

Same parts as the volume widget: bare glyphs, a pill after the name, a spec line, a meter on every row and a circular button at the end. Here the pill is the band, the meter is SNR (signal above the noise floor) and the button pins a network as Home or Metered. The menu bar icon only changes when something is wrong. Pins replace the locks

Every row ends in the same circular button as the volume widget's lock, and it cycles between three states. Open house on grey = no rule. Blue house = Home: the network you expect to be on. If it drops, its row stays in the list with a red tint. White gauge = Metered: the row gets a dashed border, and while you're connected to it the menu bar turns amber and counts the data used.

Band pill and spec line

The pill after the name is the band: 6 GHz, 5 GHz, 2.4 GHz. It is filled amber only when a network that also broadcasts on a faster band has put you on 2.4. The spec line reads generation · channel · width, the same order as the volume widget's format · channels. The last part of it changes by situation: which mesh node you're on, hotspot battery, or data used.

Why the bar is SNR

The same −65 dBm can be excellent or unusable

RSSI alone doesn't tell you much. What matters is how far the signal sits above the noise floor: −65 against −95 of noise is a 30 dB link, and against −75 it is a 10 dB link that drops calls. CoreWLAN reports both numbers, so every bar is SNR on a 0–50 dB scale. The meter notches mark the 15 and 25 dB tier edges.

No internet sits at 41 dB. Its marker shares the Healthy spot, and that's why the widget runs an internet check: the signal can't tell you when the link beyond the router is down. The system icon shows full bars either way.

Below 15 dB turns red and the Smart Bar shows the raw dBm, because at that point the number is worth reading. Between 15 and 25 dB the bar stays monochrome: a fair link is not an alert.

Build notes

What it reads, and from where

CoreWLAN through objc2

CWInterface provides rssiValue, noiseMeasurement, transmitRate, wlanChannel (band + width), activePHYMode and bssid. CWEventDelegate fires on link, SSID, BSSID and quality changes, so the bar redraws on events and needs no poll loop like the battery widget's.

Location Services gate

SSID and BSSID come back nil until the process has Location authorization. When they do, the header reads Wi‑Fi · 6 GHz, the node line is hidden, and a single menu item asks for permission. The pins need the SSID, so they appear as unavailable rather than disappearing.

Internet check

Two checks, every 30 s and on each link event: can the router be reached, and does captive.apple.com answer with its expected body. Router up with the internet down = No internet. A redirect = Sign-in required, with the primary action changed to open that sign-in page.

Scans only when the menu opens

scanForNetworks takes 1–3 s and briefly takes over the radio, so it runs only when the menu opens. The Networks list fills in once the scan returns. Rejoin disconnects and reconnects to the strongest access point for the SSID from that scan. If macOS asks for an admin password, it opens Wi‑Fi Settings instead.

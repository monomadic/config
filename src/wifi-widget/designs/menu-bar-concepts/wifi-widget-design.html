wifi-widget — menu bar concepts

Same family as battery-widget: attributed-string title, thin strikethrough-run bars, monochrome until a state deserves color, native NSMenu dropdown, style submenu persisted to ~/.config/wifi-widget/style. Each strip below shows the widget in a mocked menu bar, dark and light.

First: what "signal strength" should mean

RSSI alone is the wrong number to visualize — a −65 dBm link can be flawless or unusable depending on the noise floor. The meaningful metric is SNR = RSSI − noise, which CoreWLAN hands you directly. Map SNR to the bar fill:

SNRQualityReality
≥ 40 dBExcellentfull MCS rates, nothing to gain
25–40 dBGoodthe normal healthy range
15–25 dBFairrate stepping down, retries rising
< 15 dBPoorthis is why the video call broke up

Second honest metric worth showing: the negotiated tx rate (Mbps). It's the outcome of everything — band, width, SNR, MCS — the way watts are the outcome number on the battery widget. RSSI and noise stay available in the dropdown for debugging antennas.

Liquid Glass treatment (macOS 26/27)

The same widget over wallpaper, using the glass APIs. Two honest notes up front: the menu bar item itself can't be glass — the system menu bar supplies its own material and a status item only contributes a title/view drawn onto it — and a real NSMenu already gets the system glass appearance for free on macOS 26+. So "adopting glass" really means one decision: keep the free native menu, or replace the dropdown with a custom NSPanel hosting NSGlassEffectView, which buys richer content (live meter, tinted state) at the cost of the repo's native-menu principle.

The capsule in the menu bar strip is illustrative of the glass look, not a literal API use — the panel below is where the APIs actually apply:

  • NSGlassEffectView (macOS 26+) wraps a content view in the dynamic glass material; cornerRadius shapes it and tintColor gives the Smart-Bar warn/bad states a whole-panel tint instead of just colored text — the yellow capsule above is that idea.
  • NSGlassEffectContainerView melds nearby glass shapes into one fluid form (its spacing controls when they merge) — the bottom action row shows three buttons melded into a single lozenge, which is the API's signature trick and also cheaper to render than three separate glass views.
  • Fallbacks: gate on availability, keep the plain NSMenu path as the default style; Reduce Transparency must get an opaque background. Both fit the existing style-submenu mechanism — glass is just another persisted style, not a rewrite.
  • objc2 note: same direct-binding pattern; the glass classes are plain AppKit views, so nothing new methodologically — but check objc2-app-kit has grown the bindings before committing to the panel route.

Data sources

  • CoreWLAN (CWWiFiClient → CWInterface) — rssi, noise, txRate, ssid, bssid, channel (band + width), security, PHY mode. Same objc2 direct-binding pattern the battery widget uses for AppKit; no subprocess polling needed. Note: SSID/BSSID require Location Services authorization on modern macOS — handle the redacted case gracefully.
  • Fallback / cross-check: wdutil info (needs sudo) and system_profiler SPAirPortDataType -json (slow, fine for the dropdown). The old airport CLI is gone.
  • Internet probe: HEAD to captive.apple.com or ping the router on each refresh tick — powers the Smart Bar "no internet" state.
  • Refresh: event-driven via CWEventDelegate (link/SSID changes) plus a slow timer for RSSI drift — cheaper than the battery widget's poll-only model.

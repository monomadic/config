volume-widget — design directions

utils/volume-widget · design directions

A volume widget whose real job is silence

Sibling of battery-widget — Rust + objc2, native NSStatusItem, attributed-title bars. The twist: for a DJ, the semantics invert. Muted is the safe state. The widget shouldn't help you hear the volume — it should make it impossible to not notice when the Mac can make sound.

Direction A

Sentinel — state, not level

The menu bar shows one thing: can this machine emit sound? Muted, it disappears into monochrome. Unmuted, it turns red and stays red — no numbers needed. Quietest possible footprint; nothing animates, ever.

⌥ ⚙ 87%
Muted. Dim slashed speaker, standard menu-bar monochrome. Boring on purpose — glance up, see nothing loud, you're safe.
⌥ ⚙ 87%

Unmuted. Red speaker + volume percent. Red is reserved for exactly this — nothing else in the widget ever uses it.
⌥ ⚙ 87%
100%
Unmuted at full volume — the nightmare scenario. Icon pulses. This is the one animation Direction A allows, and it costs nothing (an NSTimer flipping alpha).
Direction B

Meter — the battery-widget family look

Reuses the strikethrough-run bar you already built. The bar shows the volume setting; when audio is actually flowing and unmuted, the bar becomes a live level meter. Feels like a channel strip living next to your battery bar.

⌥ ⚙ 87%
Muted. Empty bar, dim glyph. The empty bar itself is information: nothing can pass.
⌥ ⚙ 87%
65%
Unmuted, idle. Red fill to the set volume. Same geometry as the battery bar (40×6pt, 3pt radius) so the two widgets read as one system.
⌥ ⚙ 87%
65%
Unmuted + audio playing. Segmented meter dances with the actual output level. See the cost notes below — this is the one feature with a real price tag.
Direction C

Smart — recommended

The state machine, borrowing "Smart Bar" logic from battery-widget. One layout that morphs by state, so the safe state is nearly invisible and every step toward danger adds visual weight:

StateMenu barTreatment
Muted Dim glyph only. Monochrome, minimal width.
Unmuted, low (<25%) 18% Yellow — audible but quiet. You probably meant to do this.
Unmuted, loud 65% Red glyph + percent. Impossible to miss next to monochrome neighbours.
Unmuted + playing 65% Live meter, only while signal is present (and only if metering is enabled).
Gig Mode Green slashed speaker + padlock: mute is enforced, not just current. The only place green appears.

Gig Mode is the feature the other directions don't have. It's a CoreAudio property listener on mute/volume: if anything unmutes the device — an app, a HUD key, AirPlay handoff — the widget instantly re-mutes it and flashes a notification. You toggle it before you leave for the gig; the system physically can't sneak audio out. This costs nothing at idle (the listener is event-driven, no polling).

Native NSMenu, same as battery-widget. The header is a custom-view menu item: device name, state line, and a real slider whose track doubles as a level meter (green fill = current signal, grey knob = set volume).

Output device list matters for a DJ: mute state is per-device in CoreAudio. Muting the internal speakers doesn't mute the DJM's USB return — the widget tracks the default output and shows which device it's guarding, so there's no false confidence.

Gig Mode sits one click below Mute — armed, the menu bar goes green-locked and the item reads "Gig Mode — unlock".

Cost

What the live meter actually costs

Everything above except the dancing meter is effectively free. Three tiers, cheapest first:

free · event-driven

Mute / volume / device state

AudioObjectAddPropertyListener on mute, volume, and default-device. Zero polling, wakes only on change. Powers Directions A and C entirely, including Gig Mode enforcement.

cheap · coarse

"Is anything playing?"

kAudioDevicePropertyDeviceIsRunningSomewhere — a boolean, listenable. Enough to switch the icon between idle and playing states without touching sample data.

real cost · opt-in

Actual levels

A CoreAudio process tap (CATapDescription, macOS 14.2+) reading peak amplitude, redrawing the title at ~10 fps. Roughly 1–2% of one core while audio plays. Off by default; auto-suspends when muted or idle.

Recommendation: build Direction C on the two free tiers — that alone covers "never accidentally live at a gig" and "quickly check levels" (the set volume). Ship the tap-based meter behind a Style option ("Smart Meter"), so the animation exists when you want it and costs nothing when you don't.

Row anatomy = disk widget's. Kind icon on a dark disc (speakers, USB interface, headphones, display), name with the volume small and right-aligned, a bar underneath, and the always-visible circular control at the far right — padlock instead of eject, same opposite-polarity discs.

The gold ring marks the current output. Its stat line goes gold too (muted · 65% here). Clicking anywhere on another row switches output to it — the disk widget's "click row opens Finder" gesture, repurposed.

Transport badges sit on the disc corner like Finder's: blue Bluetooth rune for BT devices, grey USB fork for wired interfaces. Nothing for built-in.

The padlock is the gig switch. Locked on the current output it (1) pins it as default output — anything that tries to steal the route gets switched back — and (2) freezes volume and mute exactly as they are. Muted + locked is Gig Mode without needing the name. Open padlocks are translucent and brighten under the pointer, exactly like eject.

Muted device bars go dim-grey, mirroring the menu bar pill. Disconnected-but-known devices (AirPods in your pocket) list greyed at the bottom, no bar, no lock.

Semantics

What the padlock does, precisely

Lock targetEffect while locked
Current output, mutedGig Mode. Re-mutes instantly if anything unmutes; re-selects the device if anything reroutes output (AirPlay, BT auto-connect, an app grabbing the default). Menu bar shows the gold padlock.
Current output, unmutedFreezes the route and the volume level — HUD keys, apps, and auto-switching can't move it. For when you've soundchecked laptop monitoring at exactly 40%.
Non-current deviceLocks that device's own volume/mute so it comes up in a known state when something routes to it later. (Cheap to support — same listener — but cuttable if it muddies the model.)

Implementation is one pattern for all three: CoreAudio property listeners on mute / volume / default-device that re-assert the locked value the moment a change callback fires. Still no polling anywhere.

Data sources: device list + transport type from kAudioHardwarePropertyDevices and kAudioDevicePropertyTransportType (built-in / USB / Bluetooth / DisplayPort — that's also what picks the row icon); "not connected" rows come from remembering devices in the settings file after they disappear. Rows are custom NSViews with tracking areas — the disk widget's row.rs is directly reusable.
